# Streamed search and staged matches

Developer CLI Toolkit v0.1.1 resolves to `2623811347200ff5433332479ac0e2b75e3fb958`. The streaming search delays matches from each file until the scan validates its contents. The implementation uses fixed read buffers, a bounded in-memory stage, and temporary file storage for larger match sets. Matching long lines are reread through the same handle and compared with the original digest. The published project's own ADR records the change from complete-file allocation. [Published release](https://github.com/soroushneyestani/developer-cli-toolkit/releases/tag/v0.1.1) · [Search and staging source](https://github.com/soroushneyestani/developer-cli-toolkit/blob/2623811347200ff5433332479ac0e2b75e3fb958/stream_search.go) · [Long-line handling](https://github.com/soroushneyestani/developer-cli-toolkit/blob/2623811347200ff5433332479ac0e2b75e3fb958/long_line.go) · [Published engineering decision](https://github.com/soroushneyestani/developer-cli-toolkit/blob/2623811347200ff5433332479ac0e2b75e3fb958/docs/adr/0003-streaming-search.md)

The regression fixtures exercise late read errors, long matches spanning buffer fragments, changed bytes in a long matching line and removal of the spill file. The exact release commit passed native CI on Ubuntu 24.04, Windows Server 2025 and macOS 15. The evidence establishes verification of the released contract. A live tree, the sorted path list and rendering very long matches still affect resource use.
